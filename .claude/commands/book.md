Прогони книжные инструменты напрямую, в обход бота, для: **$ARGUMENTS**

Это диагностика: она отвечает на вопрос «сломан ли поиск книг» отдельно от вопроса «жив ли бот».

1. Поиск:

   ```
   PYTHONIOENCODING=utf-8 python -c "import books; print(books.find_book('$ARGUMENTS', 'ru'))"
   ```

   `PYTHONIOENCODING=utf-8` обязателен: консоль в cp1251 падает с `UnicodeEncodeError` на стрелке `←`,
   которой помечен лучший вариант. Это ошибка **печати**, а не поиска — сам поиск при этом отработал.

2. Возьми из выдачи вариант, помеченный `← лучший вариант`, и собери PDF:

   ```
   PYTHONIOENCODING=utf-8 python -c "import books; print(books.get_book_pdf('<точное название>', 'ru'))"
   ```

   Занимает от 15 с до нескольких минут — зависит от объёма. Ставь таймаут с запасом, не меньше 10 минут.
   Вызванный напрямую, `get_book_pdf` возвращает кортеж `(сообщение, путь)`; внутри бота обёртка из
   `books.tool_functions()` отдаёт только сообщение, а путь кладёт в список артефактов. Это не баг.

3. Проверь результат: файл на месте, начинается с `%PDF`, число страниц осмысленное.

Доступна только классика в общественном достоянии — Викитека для русского, Project Gutenberg для английского.
Если книга под авторским правом, инструмент её не отдаст, и это штатное поведение, а не поломка.

В конце скажи прямо: цепочка исправна или нет, и сколько заняла сборка.
