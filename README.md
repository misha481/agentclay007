# Local Agent

Агент на Python, использующий модель через [OpenRouter](https://openrouter.ai)
(по умолчанию `qwen/qwen3.5-9b`), в двух вариантах на общем ядре:

- `agent.py` — CLI-версия (REPL в терминале)
- `bot.py` — Telegram-бот (aiogram 3)

Общая логика цикла «модель ↔ инструменты» вынесена в `core.py`, поэтому оба
варианта используют одни и те же инструменты и не дублируют код.

Файловые операции реализованы через официальный MCP-сервер
[`@modelcontextprotocol/server-filesystem`](https://www.npmjs.com/package/@modelcontextprotocol/server-filesystem),
который агент запускает как подпроцесс по протоколу MCP (stdio) и ограничивает
текущей директорией проекта. Остальные инструменты — локальные Python-функции.

## Установка

```bash
pip install -r requirements.txt
npm install -g @modelcontextprotocol/server-filesystem
```

(Node.js должен быть установлен. Пакет ставится глобально, чтобы агент мог
вызывать его бинарник напрямую — через `npx` на Windows служебные npm-сообщения
попадают в stdout и ломают JSON-RPC поток MCP.)

Скопируйте `.env.example` в `.env` и укажите свой ключ OpenRouter:

```
OPENROUTER_API_KEY=sk-or-v1-...
OPENROUTER_MODEL=qwen/qwen3.5-9b
OPENROUTER_EMBED_MODEL=qwen/qwen3-embedding-8b

TELEGRAM_BOT_TOKEN=123456:AA...
TELEGRAM_ALLOWED_USERS=111111111,222222222
```

> Важно: если ключ OpenRouter или токен бота где-то «засветились» (например, были
> отправлены в чат/переписку), перевыпустите их: ключ — на openrouter.ai/keys,
> токен — через @BotFather (`/revoke`).

## Запуск CLI-версии

```bash
python agent.py
```

Далее вводите задачи в диалоговом режиме. Команда `/clear` очищает сохранённую
историю диалога, `exit` — выход.

## Запуск Telegram-бота

```bash
python bot.py
```

Команды бота: `/start`, `/help`, `/clear` (очистить историю, профиль сохранится),
`/profile` (что бот о вас помнит), `/id` (узнать свой Telegram id).

### Модель безопасности бота

Бот доступен из интернета любому, кто знает его имя, поэтому:

- **Allowlist.** Отвечает только пользователям из `TELEGRAM_ALLOWED_USERS`
  (id через запятую). Пустое значение = не пускать никого. Команда `/id`
  доступна всем — иначе новый пользователь не узнает свой id.
- **Песочница файлов.** MCP-сервер для бота запускается с корнем `workspace/`,
  а не корнем проекта. Поэтому через `fs__*` недоступны `.env` с ключами,
  исходный код и чужие профили. Проверено: попытки прочитать `../.env`,
  `.env` и абсолютный путь к нему отклоняются сервером.
- **Отдельная память.** У каждого пользователя своя история и профиль в
  `data/<user_id>/`, они не видят память друг друга.

CLI-версия работает с корнем проекта — это ваш собственный терминал.

## Инструменты агента

**Локальные (Python):**
- `roll_dice` — бросок кубиков
- `sum_numbers` — сумма чисел
- `calculate` — арифметический калькулятор
- `remember(key, value)` / `recall_facts(key?)` / `forget_fact(key)` — долговременная память о пользователе в `profile.json`
- `search_knowledge(query, top_k?)` — векторный поиск по базе знаний (см. раздел «RAG»)

**Файловые, через MCP-сервер (`fs__*`):**
- `fs__read_file`, `fs__read_text_file`, `fs__read_multiple_files`
- `fs__write_file`, `fs__edit_file`
- `fs__create_directory`, `fs__list_directory`, `fs__directory_tree`
- `fs__move_file`, `fs__search_files`, `fs__get_file_info`
- `fs__list_allowed_directories`

Доступ MCP-сервера ограничен директорией проекта (директорией `agent.py`).

## RAG — база знаний

База знаний — экспорт Telegram-канала «Афинская школа» в
`knowledge/athens_channel.json`. Поиск семантический: эмбеддинги
`qwen/qwen3-embedding-8b` через OpenRouter (`POST /api/v1/embeddings`,
размерность 4096), косинусная близость по нормализованным векторам.

Артефакты индекса рядом с базой:
- `knowledge/index.npz` — матрица векторов (float32)
- `knowledge/chunks.json` — тексты чанков + метаданные и `mtime` исходника

Индекс собирается автоматически при первом запуске `agent.py` и пересобирается,
если `athens_channel.json` изменился. Вручную:

```bash
python knowledge.py
```

Индексация всего корпуса стоит порядка $0.0002.

Детали нарезки (`knowledge.py`):
- посты режутся на куски ~1200 символов с перехлёстом 150, по границам
  абзацев/предложений;
- чанки короче 80 символов в индекс не попадают: у очень коротких постов
  («База», «Как же иначе)») эмбеддинги вырожденные и дают высокое сходство с
  любым запросом, забивая выдачу шумом;
- к поисковому запросу добавляется инструкционный префикс — Qwen3-Embedding
  обучена на асимметричной схеме «инструкция+запрос против документа».

Текущий корпус: 85 постов с текстом → 93 чанка.

## Память

Память реализована классом `MemoryStore` (`memory.py`) — он привязан к директории,
поэтому у CLI и у каждого пользователя Telegram своя память:

| | История диалога | Профиль |
|---|---|---|
| CLI (`agent.py`) | `memory_history.json` | `profile.json` |
| Бот, пользователь N | `data/N/memory_history.json` | `data/N/profile.json` |

- История сохраняется после каждого хода и подгружается при следующем запуске
  (последние 200 сообщений).
- Долговременные факты записывает инструмент `remember`. Профиль подгружается
  заново и вставляется в системный промпт **перед каждым запросом к модели**,
  поэтому только что запомненный факт сразу доступен агенту.
- Инструменты памяти замкнуты на конкретный `MemoryStore`, так что `remember`
  всегда пишет в память того пользователя, который его вызвал.

Каталоги `data/` и `workspace/`, а также `.env` содержат локальные данные и
секреты — добавьте их в `.gitignore`, если заведёте git.
